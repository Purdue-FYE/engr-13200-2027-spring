MATLAB Programming Standards in ENGR 132#

Programming standards are guidelines for writing clear, well-documented code that can be understood and used by others. All MATLAB code submitted in ENGR 132 must follow the standards described on this page.

Why Follow Programming Standards?#

Following programming standards helps you:

  • Write readable code. Your code should be understandable by team members, graders, instructors, and future colleagues.

  • Reduce errors. Well-organized, readable code is easier to test, debug, and modify.

  • Develop good programming habits. Consistently applying programming standards helps you write code that is easier to maintain and reuse.

Standards in Course Examples

Course examples will follow these programming standards whenever possible. Some examples may omit headers or comments for brevity; this does not change the requirements for submitted assignments.

Before You Submit#

Before submitting a MATLAB file, verify that your code:

  • uses the appropriate ENGR 132 template;

  • includes a complete header;

  • is organized using the sections provided in the template;

  • includes clear and useful comments;

  • uses consistent whitespace and indentation;

  • uses valid, descriptive variable names;

  • suppresses unintended Command Window output;

  • avoids unnecessary hardcoding; and

  • does not use global variables unless specifically instructed.

Use the Appropriate Code Template#

Use an ENGR 132 template for all MATLAB files submitted with an assignment. Two general templates are available:

  • Script template: Use when creating a MATLAB script.
    Download the ENGR 132 MATLAB Script Template

  • Function template: Use when creating a user-defined function.
    Download the ENGR 132 MATLAB Function Template

Some assignments provide a problem-specific template. When one is provided, use that template instead of the general course template.

Each template includes a header at the beginning of the .m file. Complete the header for every MATLAB file you submit for a grade.

Complete the Header#

The header is the comment block at the beginning of a MATLAB file. It provides information about the program, its author, and how the file should be used.

All MATLAB files submitted in ENGR 132 must include a complete header. Headers for both scripts and functions include a program description and author information. Function headers also include the function call and descriptions of the input and output arguments.

MATLAB displays information from the header in the Command Window when a user accesses the file using the help command. A complete header should provide enough information for another user to understand the purpose of the file and how to use it.

Program Description — All Scripts and Functions#

The program description briefly explains the purpose of the MATLAB file and what it is expected to accomplish. Write a clear and concise description that allows another user to understand what the code does without reading the entire file.

Author Information — All Scripts and Functions#

Complete the author information in the header of every MATLAB file you submit:

  • Assignment: Enter the assignment and problem number (e.g., 3.3.1)

  • Author: Enter your name and official Purdue email address. Do not use an email alias.

  • Team ID: Enter your section and team number. Before teams are assigned, enter only your section number.

Function Call — Functions Only#

The function call line demonstrates how to call the function using its input and output arguments. Do not include the function keyword in this line.

Input and Output Arguments — Functions Only#

Define each input and output argument with a clear, concise description. Include units when applicable.

If the function does not have input or output arguments, enter None in the appropriate location in the header.

Example Function Header#

The following example shows a complete header for a user-defined function:

function area = calc_circle_area(radius)
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
% ENGR 132
% Program Description
%   Calculate the area of a circle from its radius.
%
% Assignment Information
%   Assignment:     3.3.1
%   Author:         Purdue Pete, boiler@purdue.edu
%   Team ID:        001-01
%
% Function Call
%   area = calc_circle_area(radius)
%
% Input Arguments
%   radius - Radius of the circle (cm)
%
% Output Arguments
%   area - Area of the circle (cm^2)
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

% Function code begins here

Organize Code Properly#

Well-organized code is easier to read, understand, and debug. Organize your code using the sections provided in the ENGR 132 template:

  • Initialization: Define constants and variables, import data, and receive user input.

  • Calculations: Perform calculations and manipulate data.

  • Formatted Text & Figure Displays: Create figures and display formatted results in the Command Window.

  • Results: Paste required Command Window output or other results as comments.

Use the sections provided in the template for your assignment. If an assignment provides a problem-specific template, use the sections included in that template.

Comment Your Code#

Comments explain the purpose and logic of your code. Use comments to help another programmer understand what your code is doing and why. MATLAB uses % to begin a comment and ignores any text that follows % on that line.

Use comments to:

  • Describe variables and constants defined in the initialization section. Include units when applicable.

  • Explain the purpose of a related group of commands with a concise comment before the code.

  • Clarify code when its purpose may not be immediately apparent.

Avoid commenting every individual line of code. Comments should explain the purpose of the code rather than simply restating the command.

Example#

The following comment describes the purpose of a related group of plotting commands:

% Plot force versus time and format for technical presentation
plot(test_time, applied_force, '*')
title('Application of Force During Iron Beam Stress Test')
xlabel('Time (s)')
ylabel('Force (N)')
grid on

Format for Readability#

Consistent formatting makes code easier to read and helps communicate the structure of a program. Use whitespace and indentation to organize your code.

Whitespace#

Use whitespace to separate sections of code and make individual commands easier to read. Compare the following examples.

Poor Use of Whitespace#

% Define ball bearing parameters
bb_diameter=0.25;% ball diameter, cm
steel_density=8.05;% density of steel, g/cm^3
% Calculate the mass of the ball bearing in grams
bb_radius=bb_diameter/2;
bb_vol=4*pi*bb_radius^3/3;
bb_mass=steel_density*bb_vol;
% Display the mass to the Command Window
fprintf('The ball bearing mass is %.2f grams.\n',bb_mass)

Good Use of Whitespace#

% Define ball bearing parameters
bb_diameter = 0.25;    % ball diameter, cm
steel_density = 8.05;  % density of steel, g/cm^3

% Calculate the mass of the ball bearing in grams
bb_radius = bb_diameter / 2;
bb_vol = 4 * pi * bb_radius^3 / 3;
bb_mass = steel_density * bb_vol;

% Display the mass to the Command Window
fprintf('The ball bearing mass is %.2f grams.\n', bb_mass)

Use whitespace consistently:

  • Add a blank line between sections or related groups of code.

  • Include spaces around mathematical, relational, and logical operators.

  • Include a space after commas that separate function arguments or array elements.

  • Use spaces to align related end-of-line comments when doing so improves readability.

Indentation#

Indentation shows the structure of selection and repetition structures. Indent all commands contained within a selection or repetition structure. Increase the indentation level for each nested structure.

MATLAB vs. Python

In Python, indentation is part of the syntax and determines which commands belong to a code structure. In MATLAB, keywords such as if, for, while, and end define the structure, so indentation does not affect how the code executes. However, proper indentation is still required in ENGR 132 because it makes the structure of your code clear and easier to read.

Selection Structure#

if r == 1
    new_temp = (temp_matrix(r + 1) + temp_matrix(r)) / 2;
else
    new_temp = (temp_matrix(r - 1) + temp_matrix(r)) / 2;
end

Repetition Structure#

new_temp = temp_matrix(n, m);
temp_increase = 1;

while new_temp < boil_point
    new_temp = new_temp + temp_increase;
end

Nested Structure#

if (n < 2) || (m < 2)
    fprintf('Please enter a matrix with dimensions of at least 2x2')
else
    for row = 1:n
        for col = 1:m
            new_temp(row, col) = temp_update(temp_matrix, row, col);
        end
    end
end

Use Appropriate Variables#

Use descriptive variable names that clearly communicate what the variable represents. Avoid vague names when a more meaningful name can be used.

Compare the following examples.

Poor Variable Names#

x = 100;
y = 88;

Descriptive Variable Names#

num_students = 100;
avg_grade = 88;

The variables x and y do not communicate what the values represent. The variables num_students and avg_grade make their purposes clear.

When naming and using variables:

  • Use valid, descriptive variable names.

  • Use a consistent naming style, such as snake_case or camelCase, for variable names with multiple words.

  • Use only letters, numbers, and underscores (_) in variable names. Variable names must begin with a letter.

  • Do not use variable names that overwrite MATLAB built-in functions or constants.

  • Assign only one variable per line.

  • Assign calculation results to descriptive variables when the result will be used later in the program.

Suppress Command Outputs#

MATLAB displays the result of a variable assignment or calculation in the Command Window unless the command ends with a semicolon (;). Use semicolons to suppress output that you do not intentionally want to display.

For example:

base = 10;
height = 8;
area_tri = 0.5 * base * height;
area_para = base * height;

The semicolon at the end of each command prevents MATLAB from displaying the values of base, height, area_tri, and area_para in the Command Window.

While developing and debugging your code, you may temporarily remove semicolons to inspect values. Before submitting your code, suppress any output that is not intentionally displayed.

A semicolon is not required after commands that intentionally produce output, such as fprintf or plot.

Minimize Hardcoding#

Hardcoding occurs when a value that could change or be determined programmatically is written directly into the code. Avoid unnecessary hardcoding so your program can adapt when inputs or data change.

Compare the following examples.

Hardcoded Values#

area_tri = 0.5 * 10 * 8;
area_para = 10 * 8;

If the base or height changes, each occurrence of the value must be found and updated.

Values Assigned to Variables#

base = 10;
height = 8;

area_tri = 0.5 * base * height;
area_para = base * height;

Using variables allows the values of base and height to be updated in one location. The calculations then use the updated values automatically.

Appropriate Use of Literal Values#

Not every value written directly in code is considered improper hardcoding. Literal values may be appropriate when they are fixed by the calculation or programming structure.

Examples include:

  • mathematical coefficients, such as 0.5 in the area of a triangle;

  • fixed array indices when the position is specified by the problem; and

  • values used to define or control a repetition structure when appropriate for the problem.

Data Files#

When an assignment provides a data file, import the data into MATLAB using an appropriate function. Do not manually copy the provided data values into an array in your script or function.

Array Indices#

A fixed array index is appropriate when the position is known and does not depend on the data. For example, the following code extracts the third row of a matrix:

matrix_a = magic(5, 5);
matrix_a_row3 = matrix_a(3, :);

When an index depends on the contents or size of the data, determine the index programmatically rather than hardcoding a value that may change.

Avoid Global Variables#

Do not use global variables in ENGR 132 unless specifically instructed to do so. Global variables can make programs more difficult to understand, debug, and modify because their values can be accessed and changed from multiple locations.
